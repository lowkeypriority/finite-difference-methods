## Введение

### Актуальность проблемы
Эллиптические уравнения с переменным коэффициентом описывают широкий класс физических процессов: стационарную теплопроводность неоднородных сред, фильтрацию в пористых средах, распределение электрического потенциала в неоднородных диэлектриках.

Для численного решения на крупных сетках прямые методы (например, LU-разложение) становятся непрактичными из-за вычислительной сложности O(N³), что делает итерационные методы предпочтительными.

***Добавить краткий обзор итерационных методов со ссылками на статьи в высокоуровневых научных журналах и обоснование выбора метода Зейделя***

Метод Зейделя имеет быструю сходимость (обычно в два раза быстрее метода Якоби), но в классической формулировке является последовательным из-за зависимости обновления узла от уже обновлённых соседей.
Прямой перенос последовательного алгоритма на GPU приводит к существенным задержкам и неэффективному использованию ресурсов вычислительной системы.

Задачи:
- Разработать параллельный алгоритм метода Зейделя с красно-черным упорядочиванием, учитывающий технические характеристики GPU и выполнить его программную реализацию.
- Получить аналитические оценки времени исполнения алгоритма.
- Провести серию вычислительных экспериментов для определения метрик производительности (ускорение и пр.).
- Сравнить разработанный алгоритм с альтернативными итерационными методами (метод Якоби, последовательная CPU-версия).
- Разработать алгоритм адаптивного выбора вычислителя (CPU или GPU) для решения сеточных уравнений на сетке с заданными параметрами.
- Разработать алгоритм выбора параметров расчётной сетки и конфигурации ядер CUDA на основе технических характеристик GPU.


## 2. Постановка задачи и дискретизация

### 2.1 Модельное уравнение
Рассматривается стационарное уравнение диффузии:

$
-\nabla \cdot (a(x,y,z) \nabla u) = f(x,y,z), \quad (x,y,z) \in \Omega,
$

с граничными условиями Дирихле $u|_{\partial\Omega} = g(x,y,z)$.  
Коэффициент $a(x,y,z) > 0$ – пространственно-переменный, непрерывный.

В работе используется расчётная область 
$\Omega = [0,L_x] \times [0,L_y] \times [0,L_z]$
в форме прямоугольного параллелепипеда.

### 2.2 Конечно-разностная дискретизация
Введём равномерную расчётную сетку
$\omega_{h} = \{(x_i,y_j,z_k): x_i = i h_x,\; y_j = j h_y\; z_k = k h_z\}$
с числом узлов
$N = (N_x+1)\times(N_y+1)$,
где $h_x = L_x/N_x$, $h_y = L_y/N_y$, $h_z = L_z/N_z$.

Используем пятиточечный шаблон с аппроксимацией переменного коэффициента на гранях ячеек методом среднего арифметического:

$
-\frac{a_{i+1/2,j,k}(u_{i+1,j,k}-u_{i,j,k}) - a_{i-1/2,j,k}(u_{i,j,k}-u_{i-1,j,k})}{h_x^2} - \frac{a_{i,j+1/2,k}(u_{i,j+1,k}-u_{i,j,k}) - a_{i,j-1/2,k}(u_{i,j,k}-u_{i,j-1,k})}{h_y^2} - \frac{a_{i,j,k+1/2}(u_{i,j,k+1}-u_{i,j,k}) - a_{i,j,k-1/2}(u_{i,j,k}-u_{i,j,k-1})}{h_z^2} = f_{i,j,k}.
$

В результате получим систему линейных алгебраических уравнений
$A \mathbf{u} = \mathbf{b}$
с симметричной положительно определенной матрицей $A$ (M-матрица).

### 2.3 Классический метод Гаусса–Зейделя
- Итерационная формула (естественный порядок обхода):
$
u_{i,j,k}^{(n+1)} = \frac{1}{a_{i,i,i}} \left( b_i - \sum_{j< i} a_{i,j,k} u_j^{(n+1)} - \sum_{j> i} a_{i,j} u_j^{(n)} \right).
$
- Последовательный алгоритм имеет сложность $O(N)$ на одну итерацию, но плохо поддается распараллеливанию.



## 3. Красно-черное упорядочивание

### 3.1 Идея метода
- Разделение узлов сетки на два цветных класса (красный и черный) по правилу:
  - красный, если $(i+j+k) \mod 2 = 0$;
  - черный, если $(i+j+k) \mod 2 = 1$.
- Для пятиточечного шаблона все красные узлы зависят только от черных, и наоборот.
- **Алгоритм итерации RBGS:**
  1. Параллельно обновить все красные узлы по значениям черных с предыдущей итерации.
  2. Параллельно обновить все черные узлы по значениям красных (уже обновленных на текущей итерации).
  3. Повторять до сходимости.

### 3.2 Сходимость RBGS
- Известно, что RBGS имеет ту же скорость сходимости, что и метод Зейделя с естественным порядком для модельных эллиптических задач (теорема О`Брайена, 1960-е гг.).
- Для переменного коэффициента сходимость сохраняется, при условии что дискретизация сохраняет свойство M-матрицы.

### 3.3 Вычислительная сложность
- Одна полная итерация RBGS требует двух параллельных полуитераций (красная и черная).
- Общее количество арифметических операций совпадает с классическим методом Зейделя, но за счет параллелизма достигается ускорение на GPU.



## 4. GPU-реализация

### 4.1 Архитектура ядра CUDA
- Каждый узел сетки обрабатывается отдельной нитью (thread).
- Разбиение на блоки: блоки размером $16\times 16$ или $32\times 32$ для оптимального использования shared memory.
- Для обработки красно-черного порядка запускаются два отдельных ядра (red update, black update) или одно ядро с условной загрузкой нитей.

### 4.2 Оптимизация доступа к памяти
- Коэффициенты $a_{i,j,k}$ и $f_{i,j,k}$ загружаются в shared memory для избежания избыточных обращений к глобальной памяти.
- Использование `__restrict__` для указателей на массивы и `__ldg` для кэшированного чтения.
- Выравнивание данных по 128 байт для coalesced доступа.

### 4.3 Работа с переменным коэффициентом
- Предварительное вычисление и сохранение диффузионных потоков на гранях ячеек ($a_{i+1/2,j,k}, a_{i-1/2,j,k}, a_{i,j+1/2,k}, a_{i,j-1/2,k}, a_{i,j,k+1/2}, a_{i,j,k-1/2}$).
- В процессе итерации эти значения переиспользуются, что снижает объем вычислений.

### 4.4 Контроль сходимости
- Оценка невязки $\|A\mathbf{u}-\mathbf{b}\|_2$ или максимального изменения решения $\|\mathbf{u}^{(n+1)}-\mathbf{u}^{(n)}\|_\infty$.
- Для GPU предусмотрена асинхронная редукция с использованием shared memory (parallel reduction).



## 5. Результаты численных экспериментов

### 5.1 Конфигурация тестов
- **Аппаратное обеспечение:** NVIDIA GPU (например, Tesla V100 или RTX 3090) с CUDA 11/12; сравнение с CPU (Intel Xeon Gold 6248).
- **Тестовые примеры:**
  - Постоянный коэффициент $a=1$ (базовый тест).
  - Переменный коэффициент $a(x,y,z)=1+\alpha \sin(2\pi x) \sin(2\pi y)  \sin(2\pi z)$ с разными $\alpha$.
  - Разрывной коэффициент (двухслойная среда).
- **Размеры сеток:** от $128\times128$ до $4096\times4096$ узлов.

### 5.2 Производительность
- **Пропускная способность:** количество обновленных узлов в секунду.
- **Ускорение** = (время на CPU) / (время на GPU).
- **Эффективность использования GPU:** загрузка вычислительных ядер, процент времени на работу с памятью.

**Ожидаемые результаты (примерные):**
| Размер сетки   | CPU (сек) | GPU (сек) | Ускорение |
|----------------|----------------|-----------|-----------|
| 256×256×256    | 0.94           | 0.035     | 26.9×     |
| 512×512×512    | 15.2           | 2.17      | 7.0×      |
| 1024×1024×1024 | 61.3           | 8.66      | 7.1×      |

### 5.3 Сходимость
- Графики уменьшения логарифма невязки от номера итерации для RBGS и метода Якоби.
- Для переменного коэффициента RBGS сохраняет преимущество в скорости сходимости.
- Влияние неоднородности \(k(x,y)\) на число итераций (увеличение на 10–30% для сильной контрастности).

### 5.4 Сравнение с другими методами
- Сравнение производительности (время до достижения заданной точности) между:
  - RBGS на GPU,
  - методом Якоби на GPU,
  - последовательным GS на CPU.
- RBGS на GPU оказывается быстрее метода Якоби для сеток >512×512 из-за лучшей сходимости.



## 6. Обсуждение

### 6.1 Анализ сильных и слабых сторон
- **Сильные:** высокое ускорение для крупных задач, сохранение классической сходимости, масштабируемость на GPU.
- **Слабые:** зависимость производительности от структуры сетки (на нерегулярных сетках красно-черная схема не так эффективна), ограниченная эффективность для очень больших разрывов коэффициентов.

### 6.2 Практические рекомендации
- Для малых сеток (<256×256) накладные расходы на передачу данных на GPU могут перевешивать выгоду, лучше использовать CPU.
- При сильно разрывных коэффициентах рекомендуется использовать предобуславливатель или многосеточный метод с RBGS в качестве сглаживателя.
- Оптимальный размер блока нитей – 256 потоков (16×16).

### 6.3 Направления будущих исследований
- Гибридные схемы с динамическим распределением нагрузки на GPU.
- Сравнение с более современными итерационными методами (например, Conjugate Gradient с предобуславливанием на GPU).
